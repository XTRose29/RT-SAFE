# Benchmark protocol and reported results

RT-SAFE evaluates navigation and safety while the world continues during inference. The agent receives RGB observations, navigation instructions, recent action frames, and seven movement markers. It selects from 16 discrete move, turn, or wait actions.

| Axis | Reported setting |
|---|---|
| Routes | 36 over five city maps |
| Difficulty | Easy, medium, hard; 60%, 80%, 100% authored actor activation |
| Timing | Real-time world evolution during planning; static world paused during inference |
| Observation | 720 × 640 RGB, 100° horizontal field of view; previous-action frames at approximately 0.5 simulated seconds |
| Completion | Success rate and success weighted by path length (SPL) |
| Safety | Physical contacts, trip/oil/water events, traffic-rule violations |
| Timing attribution | Active events during execution; passive events during inference |
| Safe success | Successful completion with zero recorded safety events across the evaluated categories |

The detailed implementation protocol is in [benchmark/DEFAULT_SETTINGS.md](../benchmark/DEFAULT_SETTINGS.md). Presets are explicit configuration snapshots. `hard` is called `default` in parts of the legacy low-level runner.

## Results in the website

`website/app/data.json` and `website/public/data/results.csv` are extracted from the supplied manuscript archive dated 2026-10-01. The matched hard comparison contains 36 routes per model per timing mode, with eight models (288 paired episodes). All-difficulty summaries contain 108 episodes per model. Do not mix these denominators.

For the matched hard comparison, success is 91.3% static and 94.1% real-time; safe success is 19.8% and 0.7%. Mean contacts per episode rise from 3.31 to 40.68. These are manuscript results, not fresh measurements made during repository preparation.

## Matched 20-task default-reasoning leaderboard

The default website view compares nine models on the same 20 routes across four
maps, five tasks per map, at hard difficulty in real time with seed 0 (180
episodes). Gemini 4 Argon uses explicit medium, its configured default; the eight
historical models use their recorded provider-default settings. These are
September historical runs and October Gemini 4 runs through different serving
transports, not a simultaneous controlled comparison. Original scoring, including
curb scoring, is retained for every model.

The ten original routes are extended with five routes each on maps 3 and 4.
The extension was selected from route geometry before Gemini outcomes: shortest
and longest zero-crossing routes, shortest and longest one-crossing routes, then
the upper-median remaining route by length. Selection details and source records
remain in the local audit; the public data includes the selection hash.

`website/scripts/build-matched-default-results.py` refuses incomplete sets or
duplicate tasks and verifies finalized status, task, seed, hard difficulty,
real-time timing, reasoning and identical runtime route points across all models.
All failures stay in the denominator. Success, collisions, SPL, decision counts
and latency use equal episode weighting; latency averages episode means.
`website/public/data/matched-default-results.json` contains the aggregate metrics,
serving provenance, action summaries and termination counts. The matching PNG/PDF
is generated by `website/scripts/plot-matched-default-results.py` with matplotlib.

The default table, its CSV and the chart use only this 20-task set. The earlier
10-task all-effort table and manuscript results remain separately selectable.
The low-reasoning Gemini 4 pilot is labeled historical and remains unranked.

## Balanced ten-task hard real-time leaderboard

The separately selectable ten-task leaderboard reaggregates a fixed selection of 10 existing tasks
across two maps, five per map, at hard difficulty in real time with seed 0. All
24 model/effort configurations use exactly the same tasks: 240 recorded episodes.
This is a subset of the existing September campaign, not a newly collected private
evaluation. The full manuscript tables and their denominators remain available
through the evaluation controls and are unchanged.

Selection uses authored crossing counts and recorded reference-route lengths,
without consulting model outcomes. Each map contributes two routes with zero
authored crossings, two with one, and one with multiple authored crossings.
Route lengths span approximately 22–160 m. Authored counts describe task
stratification; they are not counts of crossing events observed during execution.

`website/scripts/build-subset-results.py` reads a frozen local manifest and each
cell's current completed status. It checks the task, seed, hard configuration,
real-time timing, reasoning setting, and identical reference-route lengths.
Incomplete configurations fail aggregation. Failed navigation remains in the
denominator. Metrics use equal episode weights; latency is the mean of episode
mean response times, and SPL comes from the recorded benchmark metrics.

The subset generator regression tests run with the website tests (`npm test`)
and require Python 3; they use only the Python standard library.

The selected task IDs and source-file audit stay outside this public repository.
The public aggregate is `website/public/data/subset-results.json`; its manifest
SHA-256 identifies the frozen selection. The website CSV export carries the
suite ID, episode count, map count, and seed with every configuration.

```bash
python3 website/scripts/build-subset-results.py \
  --manifest /path/to/local/manifest.json \
  --main-root /path/to/main/campaign \
  --claude-root /path/to/claude/campaign \
  --audit /path/to/local/audit.json
```

## Interpretation limits

- Static and real-time prompts differ in timing advice, so their comparison is not a pure timing-only intervention.
- Repeated contact callbacks may count as multiple collisions. Collision count is not a count of distinct accidents.
- Hazard evaluation uses endpoint overlap; water is recorded without a movement perturbation in the reported version.
- CLI, direct API and routing-provider transports may add different model-visible context. Keep access surfaces labeled.
- The separate offline BC/RL study uses a fixed three-second delay and 16 held-out tasks. Its results are included, but its training implementation, dataset and checkpoints have not been located in the supplied benchmark tree.
- The current source snapshot contains research changes made after some campaigns. Exact paper reproduction requires the recorded runtime, serving versions, per-run resolved configuration and campaign source snapshot.

Raw rollouts contain more metadata than a public result table needs. The repository includes only curated decision examples and aggregate manuscript tables, not private campaign logs or account-usage records.
